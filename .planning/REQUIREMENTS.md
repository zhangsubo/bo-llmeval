# Requirements: LLM API 服务评测管理平台

**定义时间：** 2026-08-18
**核心价值：** 在相同测试输入、参数、负载和 Tokenizer 口径下，客观横向比较供应商 LLM API 服务的性能、质量和成本，为生产准入提供可复现证据。

## v1 需求

### 供应商与连接管理

- [ ] **SUPP-01**: 用户可以创建供应商记录（名称、简称、类型、状态、备注）
- [ ] **SUPP-02**: 用户可以为供应商创建服务连接（Base URL、API Key、区域、限额）
- [ ] **SUPP-03**: 用户可以测试连接的流式和非流式 Chat Completions 能力
- [ ] **SUPP-04**: 用户可以通过 `/v1/models` 自动同步模型列表
- [ ] **SUPP-05**: 用户可以手工录入模型 ID 作为兜底
- [ ] **SUPP-06**: 用户可以替换 API Key，系统阻止运行中任务的密钥替换
- [ ] **SUPP-07**: 系统使用应用层加密存储 API Key，页面只显示掩码
- [ ] **SUPP-08**: 系统通过域名/CIDR 白名单阻止 SSRF 和内网请求

### 模型与对比组

- [ ] **MODEL-01**: 用户可以创建模型部署记录（model ID、展示名称、上下文窗口、流式能力）
- [ ] **MODEL-02**: 用户可以人工创建模型对比组并选择成员
- [ ] **MODEL-03**: 用户可以为模型对比组指定默认 Tokenizer
- [ ] **MODEL-04**: 用户可以维护模型价格（输入/输出/缓存 Token 单价、币种、汇率）
- [ ] **MODEL-05**: 系统在任务快照中记录价格版本，汇率变化只影响未来任务

### 测试资源管理

- [ ] **RES-01**: 用户可以一键下载并缓存 Tokenizer（ModelScope 或 Hugging Face）
- [ ] **RES-02**: 用户可以上传本地 Tokenizer 目录作为兜底
- [ ] **RES-03**: 系统内置常用 tiktoken encoding
- [ ] **RES-04**: 用户可以下载内置质量数据集（IFEval、C-Eval、MMLU、GSM8K、MGSM、HumanEval、MBPP）
- [ ] **RES-05**: 用户可以上传自定义数据集（JSONL/CSV，单文件 100MB 上限）
- [ ] **RES-06**: 系统对数据集执行全文件校验，不接受部分成功
- [ ] **RES-07**: 用户可以使用系统内置测试方案模板（冒烟、快速基线、标准基线、并发梯度、固定 RPS、稳定性、轻量质量）
- [ ] **RES-08**: 用户可以复制并自定义测试方案模板

### 任务创建与预检

- [ ] **TASK-01**: 用户可以从模板创建评测任务草稿
- [ ] **TASK-02**: 用户可以选择一个或多个模型部署作为测试目标
- [ ] **TASK-03**: 用户可以选择串行或并行运行 Run
- [ ] **TASK-04**: 用户可以确认数据集、Tokenizer、生成参数、负载和限额
- [ ] **TASK-05**: 系统执行强制预检（连接状态、流式能力、资源就绪、上下文窗口、限额、Worker 健康）
- [ ] **TASK-06**: 系统按目标和检查项展示"通过、警告、阻断"，并给出失败原因和修复入口
- [ ] **TASK-07**: 预检通过后系统冻结配置快照并进入 FIFO 队列

### 队列与执行

- [ ] **EXEC-01**: 系统使用 PostgreSQL 作为唯一数据库和持久化 FIFO 队列
- [ ] **EXEC-02**: 系统全局默认最多同时运行 4 个 Run（可配置）
- [ ] **EXEC-03**: 系统按入队时间 FIFO 执行 Run，无优先级或插队
- [ ] **EXEC-04**: 系统支持固定并发、固定 RPS/open-loop、阶梯负载模式
- [ ] **EXEC-05**: 系统在正式请求前发送预热请求，冷启动和稳态独立统计
- [ ] **EXEC-06**: 系统支持内置长度预设（短 256/128、中 2K/512、长 8K/1K）
- [ ] **EXEC-07**: 系统使用 EvalScope 通过 Python API 执行评测，禁止拼接 shell 命令

### 监控、取消与重试

- [ ] **MON-01**: 用户可以查看任务和 Run 状态、排队位置、进度、已用时间和预计剩余时间
- [ ] **MON-02**: 用户可以查看当前并发、目标/实际 RPS、成功率、错误率
- [ ] **MON-03**: 用户可以查看 Latency、TTFT、Token 速度和吞吐的当前汇总
- [ ] **MON-04**: 页面每 2–5 秒自动刷新监控数据
- [ ] **MON-05**: 用户可以取消整项任务或单个 Run
- [ ] **MON-06**: 系统在点击取消后 5 秒内停止发送新请求
- [ ] **MON-07**: 用户可以对失败 Run 执行人工重试，系统创建新 Run 而不覆盖原 Run
- [ ] **MON-08**: 用户可以从历史任务一键复测，系统创建新草稿并展示配置差异

### 性能与质量评测

- [ ] **PERF-01**: 系统记录每个请求的总耗时、TTFT、TPOT、ITL、生成速度、峰值速度、峰值 TPS
- [ ] **PERF-02**: 系统同时记录供应商 usage 和本地 Tokenizer 两套 Token 数据
- [ ] **PERF-03**: 系统对性能指标提供 mean、min、max、P50、P90、P95、P99
- [ ] **PERF-04**: 系统独立聚合冷启动、预热和正式稳态数据
- [ ] **PERF-05**: 系统对性能请求不自动重试，保留真实失败率和延迟
- [ ] **QUAL-01**: 系统支持客观质量评分（exact match、normalized exact match、regex match、多项选择准确率、数值容差、代码单元测试）
- [ ] **QUAL-02**: 系统对质量请求的临时网络错误、超时、429 和 5xx 执行有限自动重试（默认最多 2 次）
- [ ] **QUAL-03**: 系统在独立代码 Worker 的隔离容器中执行 HumanEval 和 MBPP 代码测试
- [ ] **QUAL-04**: 代码执行容器禁止外网、受 CPU/内存/时间/进程数限制

### 协议兼容

- [ ] **PROTO-01**: 系统支持 OpenAI-compatible Chat Completions 流式和非流式模式
- [ ] **PROTO-02**: 系统支持多轮对话（按顺序发送并携带历史消息）
- [ ] **PROTO-03**: 系统支持 Tool Calling（传入 tools 和 tool_choice，校验 tool_calls 结构）
- [ ] **PROTO-04**: 系统保留完整原始响应 JSON 并提取已知扩展字段
- [ ] **PROTO-05**: 系统对未识别扩展字段原样保留，不因未知字段判定失败

### 结果与对比

- [ ] **RESULT-01**: 用户可以查看任务汇总、Run 汇总、请求明细和 Attempt 明细
- [ ] **RESULT-02**: 用户可以查看完整 Prompt/messages、模型回答、原始响应 JSON 和错误正文
- [ ] **RESULT-03**: 系统按请求列表强制分页，正文只在打开单条详情时按需加载
- [ ] **RESULT-04**: 用户可以选择任意终态历史 Run 进行对比
- [ ] **RESULT-05**: 系统自动检查对比条件一致性（数据集、Tokenizer、参数、负载）
- [ ] **RESULT-06**: 系统对条件一致的 Run 标记"严格可比"，有差异时标记"非严格可比"并展示差异项
- [ ] **RESULT-07**: 系统提供指标对比表、分位数图表、时间序列、错误分类图、成本对比

### 报告与导出

- [ ] **REPORT-01**: 用户可以手工生成静态多页 HTML 报告（首页、摘要、性能、质量、成本、错误、对比）
- [ ] **REPORT-02**: 系统将所有完整请求内容放入独立 `request-details.html`
- [ ] **REPORT-03**: 删除 `request-details.html` 后其他页面仍可完整查看
- [ ] **REPORT-04**: 报告可在断网环境的桌面 Chrome 中打开，不依赖 CDN
- [ ] **REPORT-05**: 每次生成创建新的不可变报告版本，旧版本长期保留
- [ ] **REPORT-06**: 用户可以添加和修改任务或 Run 的人工备注
- [ ] **REPORT-07**: 用户可以导出汇总 CSV 和完整任务/Run/Request JSON
- [ ] **REPORT-08**: 系统对导出数据脱敏 API Key、认证 header 和其他已知秘密

### 安全与审计

- [ ] **SEC-01**: 系统在页面、日志、CSV、JSON 和 HTML 报告中统一脱敏 API Key
- [ ] **SEC-02**: 系统渲染 Prompt、回答、错误和扩展字段时按纯文本转义，不执行 HTML/Markdown/JavaScript
- [ ] **SEC-03**: 系统对 CSV 导出的公式字符做安全转义
- [ ] **SEC-04**: 系统记录关键操作审计日志（供应商/连接配置、API Key 替换、任务创建/取消/重试、报告生成、白名单修改、历史清理）
- [ ] **SEC-05**: 系统在连接测试、任务预检和实际请求前重新解析域名并校验白名单
- [ ] **SEC-06**: 系统防止 DNS rebinding，不自动跟随 HTTP 重定向
- [ ] **SEC-07**: 系统支持按连接配置"忽略 TLS 错误"，默认关闭，需要二次确认

### 系统健康与运维

- [ ] **SYS-01**: 用户可以查看仪表盘（当前排队/运行/取消中任务、最近完成/失败任务、异常摘要）
- [ ] **SYS-02**: 用户可以查看组件健康状态（Web/API、PostgreSQL、普通 Worker、代码 Worker、报告目录、Tokenizer 缓存）
- [ ] **SYS-03**: 用户可以配置域名/CIDR 白名单，修改需要输入确认文本并写审计日志
- [ ] **SYS-04**: 用户可以预览并手工清理历史任务数据（按截止日期和终态状态）
- [ ] **SYS-05**: 系统清理操作生成唯一批次和待删除清单，支持幂等补偿重试
- [ ] **SYS-06**: 系统清理删除任务、Run、请求/Attempt、业务日志、备注和报告文件
- [ ] **SYS-07**: 系统清理保留供应商、连接、模型、对比组、Tokenizer、数据集、模板和清理审计记录

## 明确排除

| 功能 | 原因 |
|------|------|
| 客户自助测试 SaaS | 首版仅服务内部，不面向外部客户 |
| 公开排行榜 | 不公开供应商比较结果 |
| 自动准入结论 | 平台只记录客观结果，不替业务负责人决策 |
| Responses API | 聚焦 Chat Completions，协议差异大 |
| 供应商原生协议 | 仅支持 OpenAI-compatible，无法满足规范的供应商不接入 |
| 文本以外的模型类型 | 首版聚焦文本 LLM |
| 全量搬运 OpenCompass/EvalScope 数据集 | 按需精选，避免 license 和存储问题 |
| 暂停续跑、断点续跑 | 简化首版，Worker 中断后用户可手工重试 |
| 性能请求自动重试 | 保留真实失败率和延迟分布 |
| Redis、Celery、Elasticsearch | PostgreSQL 足以满足首版，技术栈最小化 |
| Kubernetes | Docker Compose 足以满足首版容量 |
| 在线分享链接 | 离线报告已满足内部分享需求 |
| 报告托管服务 | 静态文件手工复制即可 |
| 多语言界面 | 首版仅中文 |
| 移动端适配 | 首版仅桌面 Chrome |
| 自动数据清理 | 手工预览清理，避免误删 |
| 内置数据库备份 | 由外部运维体系负责 |
| 实时汇率 | 手工维护汇率足以满足首版 |
| 自动 PII 检测/脱敏 | 上传前提示用户手工脱敏 |
