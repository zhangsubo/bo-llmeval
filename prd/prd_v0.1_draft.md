## 1. 需求背景

### 1.1 业务背景

公司作为大模型服务提供商，需要接入二十余家原厂或云服务商的大模型 API，并对外提供统一的 LLM 服务。供应商接入前及服务变更后，需要在一致条件下验证协议兼容性、稳定性、性能、成本和基础模型能力。

首版平台服务内部生产准入与供应商横向选择，不面向客户提供自助测试 SaaS，不建设公开排行榜，也不代替业务负责人作出准入结论。

### 1.2 现状与痛点

- 供应商 Base URL、API Key、模型 ID、Tokenizer、价格、限额和测试参数散落，难以统一维护。
- 测试依赖 CLI、脚本和人工配置，操作门槛高，批量对比供应商耗时且容易产生口径差异。
- 缺少统一任务队列、状态监控、取消、失败定位、复测和历史追踪能力。
- 流式与非流式、供应商 usage 与本地 Tokenizer、冷启动与稳态等数据口径容易混淆。
- 结果散落在日志或单机文件中，无法稳定复现、横向比较或生成可人工外发的离线报告。
- 压测参数如果配置不当，可能突破供应商配额或对生产服务产生冲击。

### 1.3 外部研究结论

- EvalScope 同时提供能力评测、API 性能压测、客观评分和结果输出，首版将其作为唯一评测执行引擎。
- OpenCompass 主要用于数据集、评测方法和可复现性参考，不单独部署，不全量搬运其数据集。
- token-speed-tester 聚焦流式速度测量，首版仅借鉴指标命名、峰值算法和报告表达，不作为运行依赖。
- PostgreSQL 原生能力足以承担首版业务数据、持久化 FIFO 队列、JSON 结果和分位数统计，不引入 Redis、Celery 或 Elasticsearch。

研究详情见 [官方资料研究报告](../research/official_source_research_v0.1.md)。

## 2. 产品目标与成功标准

### 2.1 产品目标

1. 统一管理供应商、服务连接、模型部署、模型对比组、Tokenizer、数据集、价格和测试方案。
2. 通过可视化界面创建、监控、取消、重试和复测评测任务，不要求用户直接操作 CLI。
3. 在相同测试输入、参数、负载和 Tokenizer 口径下横向比较供应商服务。
4. 同时覆盖协议兼容、稳定性、性能、成本与轻量客观质量回归。
5. 保留可复现的原始证据，并生成可人工复制、离线查看、可删敏感明细页的静态报告。
6. 通过连接级限额、任务预检和即时取消，降低误压测、超配额与内网请求风险。

### 2.2 成功指标

| 目标类型 | 衡量指标 | 首版目标值 | 验证方式 |
|---|---|---|---|
| 接入效率 | 从创建连接到完成模型冒烟测试 | 不超过 10 分钟 | 新供应商验收演练 |
| 任务效率 | 使用模板创建一个多供应商评测任务 | 不超过 5 分钟 | 可用性测试 |
| 可复现性 | 能否追溯数据集、Tokenizer、参数、价格和连接快照 | 100% 的已启动任务可追溯 | 抽查任务快照 |
| 取消能力 | 点击取消后停止发送新请求 | 不超过 5 秒 | 并发压测验收 |
| 报告能力 | 离线 Chrome 打开报告；删除 `request-details.html` 后摘要仍可用 | 100% 通过 | 断网验收 |
| 密钥安全 | 页面、日志、导出和报告出现 API Key 明文 | 0 次 | 自动扫描与人工检查 |
| 页面性能 | 常用列表和任务汇总接口 P95 | 不超过 2 秒 | 基准容量下压测 |

### 2.3 产品原则

- 平台记录和对比客观结果，不自动给出准入结论、最佳供应商、综合分或加权排名。
- 原始测试结果不可修改；人工备注独立存储并形成报告快照。
- 对比条件不一致时允许查看，但必须明确标记“非严格可比”。
- 性能测试不自动重试请求，避免修饰真实失败率和延迟。
- 优先复用 EvalScope，平台只建设缺失的业务管理与安全闭环。

## 3. 用户与使用场景

### 3.1 用户角色

首版不实现用户、角色和权限管理。能够通过公司可信网络、VPN 或统一网关访问域名的人员均可使用全部功能。

| 业务角色 | 核心诉求 | 首版限制 |
|---|---|---|
| 评测人员 | 快速创建任务、查看进度、比较性能和质量、导出证据 | 平台不替其给出准入判断 |
| 供应商管理人员 | 维护供应商、连接、模型、价格、配额及人工备注 | 不提供外部价格系统实时同步 |
| 技术人员 | 排查兼容性错误、查看逐请求数据、管理 Tokenizer 与数据集 | 不允许从页面启动或停止基础服务 |
| 运维人员 | 查看系统健康、磁盘空间、Worker 心跳并执行历史数据清理 | 数据库备份由外部运维体系负责 |

审计日志预留 `actor_type`、`actor_id` 和外部身份字段，为后续 SSO 接入提供基础；首版操作者身份记为匿名，并记录来源 IP。

### 3.2 核心使用场景

1. 新供应商接入：建立供应商和连接，录入 Base URL 与 API Key，同步或手工录入模型，完成流式/非流式冒烟测试。
2. 同类模型横向选择：将多个模型部署加入人工建立的模型对比组，使用同一模板和数据集执行性能或质量任务。
3. 生产变更回归：基于历史任务“一键复测”，核对配置差异后重新执行，比较历史表现。
4. 故障定位：在任务监控和逐请求详情中查看状态码、错误正文、供应商 request ID、耗时与响应结构。
5. 内部评审与外发：添加人工备注，手工生成静态多页 HTML；外发前可删除完整请求明细页。

### 3.3 User Journey Map

| 阶段 | 用户行为 | 当前痛点 | 平台能力 | 完成标志 |
|---|---|---|---|---|
| 接入 | 新建供应商、连接和模型 | 参数散落、协议差异难发现 | 配置向导、连接测试、模型同步 | 至少一种 Chat Completions 模式可用 |
| 准备 | 下载数据集和 Tokenizer、选择模板 | 依赖路径和版本难管理 | 一键下载、校验、版本冻结 | 所需资源状态均为“就绪” |
| 创建 | 选择目标、参数、负载和数据集 | 多目标参数难保持一致 | 模板、批量目标、差异提示 | 预检通过并进入队列 |
| 执行 | 监控进度、错误和实时指标 | CLI 状态分散、取消困难 | 统一状态、2–5 秒刷新、即时取消 | 任务进入终态 |
| 分析 | 比较性能、质量、成本和错误 | 口径不一致、结果难追溯 | 严格可比检查、图表、原始证据 | 完成分析与备注 |
| 分享 | 生成人工外发材料 | 手工拼表、敏感信息难处理 | 多页离线报告、独立明细页 | 获得不可变报告版本 |

## 4. 产品范围

### 4.1 首版范围

- 仅测试文本生成 LLM。
- API 协议锁定 OpenAI-compatible Chat Completions。
- 同时支持流式和非流式调用。
- 认证方式仅支持 `Authorization: Bearer <API_KEY>`。
- 支持供应商、连接、模型部署、对比组、Tokenizer、数据集、模板和价格管理。
- 支持冒烟、基线性能、并发/固定 RPS/阶梯压测、稳定性和轻量客观质量评测。
- 支持多轮文本对话和 Tool Calling 协议结构校验，但不执行工具。
- 支持代码生成结果在隔离沙箱中自动评分。
- 支持任务队列、监控、取消、质量请求有限重试、人工重试和一键复测。
- 支持结果对比、CSV/JSON 下载和离线静态多页 HTML 报告。

### 4.2 首版非目标

- 客户自助测试 SaaS、用户权限、SSO、公开排行榜和自动准入结论。
- Responses API、供应商原生协议及文本以外的模型类型。
- 定时任务、公开自动化 API、Webhook 和外部消息通知。
- 主观写作评测、LLM-as-a-Judge、Agent 工具执行。
- 全量搬运 OpenCompass/EvalScope 数据集或单独部署 OpenCompass。
- 暂停续跑、断点续跑、性能请求自动重试。
- Redis、Celery、Elasticsearch、Kubernetes。
- 在线分享链接、报告托管、多语言和移动端适配。
- 自动清理、内置数据库备份、实时汇率和正式接入外部价格系统。
- 任意 Python 评分脚本和自动 PII 检测/脱敏。

## 5. 信息架构

首版提供 8 个一级入口：

1. **仪表盘：** 最近任务、异常概览、系统健康与资源余量。
2. **供应商：** 供应商及服务连接管理。
3. **模型：** 模型部署、模型对比组和价格管理。
4. **测试资源：** Tokenizer、性能数据集、质量数据集和测试方案模板。
5. **评测任务：** 草稿、队列、执行、监控、取消、重试和复测。
6. **结果对比：** 跨 Run 或跨任务对比、可比性检查和图表。
7. **静态报告：** 报告生成、版本记录和文件位置。
8. **系统设置：** 全局并发、基准币种、域名/CIDR 白名单及历史数据清理。

## 6. 核心领域模型

### 6.1 对象关系

| 对象 | 定义 | 关键关系 |
|---|---|---|
| 供应商 Supplier | 原厂、云厂商或其他 API 服务提供方 | 一个供应商可有多个服务连接 |
| 服务连接 Service Connection | 一组账号、区域、Base URL、Bearer API Key 和连接策略 | 一个连接只能绑定一把 API Key，可包含多个模型部署 |
| 模型部署 Model Deployment | 可实际调用的 `model` ID 及其服务元数据 | 隶属一个连接，可加入一个模型对比组 |
| 模型对比组 Comparison Group | 人工认定为同类、可横向比较的一组模型部署 | 绑定默认 Tokenizer |
| Tokenizer 版本 | 可复现的 Tokenizer 资源 | 被对比组、模板和任务快照引用 |
| 数据集版本 | 性能输入或质量样本的不可变版本 | 被测试模板和任务快照引用 |
| 测试方案模板 | 可复用的场景、参数、负载与资源组合 | 使用后修改会创建新版本 |
| 评测任务 Evaluation Task | 一次用户创建的多目标评测集合 | 包含一个或多个 Run |
| 评测 Run | 一个模型部署在一个测试场景中的执行单元 | 包含请求、尝试、指标和错误 |
| 请求 Request | 一个样本或一轮请求的逻辑记录 | 质量请求可包含多个 Attempt |
| 请求尝试 Attempt | 实际发送的一次 HTTP 请求 | 保存时序、响应、usage、错误和 request ID |
| 人工备注 Note | 对任务或 Run 的外部解释 | 不修改原始测试数据 |
| 静态报告版本 | 手工生成的不可变离线快照 | 快照任务结果、备注和生成时间 |
| 审计记录 Audit Event | 关键配置与操作记录 | 不保存密钥或完整业务正文 |

### 6.2 不可变快照

任务进入队列前必须冻结并保存：

- 供应商、连接和模型部署标识及展示名称。
- Base URL、模型 ID、流式能力、服务层级和 TLS 忽略状态；不保存可展示的 API Key 明文。
- 数据集版本、checksum、样本范围与 Prompt 模板。
- Tokenizer 来源、版本、checksum 和 Chat 模板。
- 生成参数、负载参数、超时、重试、预热和限额。
- 输入、输出和缓存 Token 价格、币种、汇率及折算价。
- EvalScope 版本及平台版本。

历史结果不得因后续配置、价格、密钥、备注或资源版本变化而改变。

## 8. 详细功能需求

### 8.1 仪表盘与系统健康（F-01）

#### 8.1.1 仪表盘内容

- 当前排队、运行、取消中的任务数量。
- 最近完成、部分完成、失败和取消的任务。
- 近期开启“不安全 TLS”的任务、429、5xx、超时和流中断异常摘要。
- 最近生成的静态报告及版本。
- 数据库、普通 Worker、代码 Worker、报告目录和 Tokenizer 缓存目录健康状态。

#### 8.1.2 健康状态

只读展示以下组件：Web/API、外部 PostgreSQL、普通 Worker、代码 Worker、静态报告目录、Tokenizer 缓存目录。每项显示最近心跳、状态、延迟或剩余磁盘空间。页面不提供服务启动、停止或重启按钮。

#### 8.1.3 验收标准

- Worker 心跳超时后，仪表盘在一个刷新周期内显示异常。
- 磁盘不足、数据库不可达或代码 Worker 离线时给出可操作提示。
- 健康异常不自动修改已经完成的历史任务状态。

### 8.2 供应商与服务连接（F-02、F-03）

#### 8.2.1 供应商

- 字段：名称、简称、类型、外部供应商 ID（预留）、状态、备注、创建/更新时间。
- 状态：启用、停用、归档。
- 不提供物理删除；停用或归档后不得用于新任务，历史任务仍可查看。

#### 8.2.2 服务连接

- 一条服务连接表示一个供应商账号/区域/端点/API Key 组合。
- 配置字段：连接名称、供应商、区域/服务层级、Base URL、Bearer API Key、模型同步策略、TLS 忽略开关、超时、限额、状态、备注。
- Base URL 只填写域名和可选业务前缀，不填写 `/v1`；平台去除末尾 `/`，派生 `/v1/models` 和 `/v1/chat/completions`。
- 首版仅允许 `http` 或 `https`，仅支持 Bearer API Key；无法满足规范的供应商不接入。
- API Key 由页面录入，在 PostgreSQL 中使用应用主密钥加密；主密钥由受保护的 `.env` 提供。
- 保存后仅显示掩码，不提供查看或复制明文，只能替换。
- 一个连接只绑定一把 API Key；多账号、多 Key 必须建立多条连接，不做 Key 池、轮换或负载均衡。

#### 8.2.3 API Key 替换

- 关联连接存在排队中或运行中任务时禁止替换。
- 替换成功后，未来任务使用新 Key；历史任务不变。
- 旧密文物理删除，只保留不含秘密的凭证版本号和更新时间。
- 替换操作必须写审计日志，日志不得包含新旧 Key。

#### 8.2.4 连接测试

1. 允许先保存草稿。
2. 校验 Base URL、网络白名单、DNS/IP、TLS 和 API Key 是否已配置。
3. `/v1/models` 可用时自动同步模型列表；不可用不阻断接入。
4. 用户选择或手工录入准确 `model` ID。
5. 分别发送非流式和流式 Chat Completions 冒烟请求。
6. 至少一种模式成功时可将连接标记为“可用”，同时独立记录两种模式的能力状态。
7. 保存响应状态、耗时、供应商 request ID 和脱敏错误正文。

平台不跟随 HTTP 3xx；3xx 记为兼容性错误。开启“忽略 TLS 错误”时必须二次确认并写审计；该开关仅对当前连接生效，默认关闭，不能绕过域名/CIDR 和特殊地址阻断。

### 8.3 模型部署、对比组与价格（F-04、F-05）

#### 8.3.1 模型部署

字段包括：实际 `model` ID、展示名称、连接、对比组、上下文窗口、最大输出长度、流式/非流式支持、Tokenizer、模型版本、服务层级、来源（同步/手工）、备注、状态。

模型部署允许停用或归档，不提供物理删除。来源于 `/v1/models` 的记录可以补充人工元数据，但不得擅自改写实际 model ID。

#### 8.3.2 模型对比组

- 由人工创建并选择成员，平台不按名称模糊匹配。
- 一个模型部署首版最多属于一个对比组。
- 对比组指定默认 Tokenizer，用于同类模型的统一性能口径。
- 若任务对目标使用不同 Tokenizer，结果标记为非严格可比。

#### 8.3.3 价格与币种

- 每个模型部署维护输入、输出、缓存 Token 单价、计价单位、原始币种、生效时间、价格版本和来源。
- 预留外部供应商 ID、外部模型 ID、价格来源（manual/external）、外部版本和最后同步时间。
- 首版只允许人工维护，不连接外部供应商管理系统，也不提供匿名价格写入 API。
- 平台基准币种默认为 CNY；非 CNY 价格由管理员维护手工汇率。
- 任务快照原始价格、汇率和 CNY 折算价；汇率变化只影响未来任务。
- 有供应商 usage 时计算实际成本；无 usage 时用本地 Tokenizer 估算并明确标记“估算”。

### 8.4 Tokenizer 管理（F-06）

- 支持输入 ModelScope 或 Hugging Face 模型 ID，一键下载、缓存和校验 Tokenizer。
- 常用 tiktoken encoding 可内置，不要求额外下载。
- 支持上传本地 Tokenizer 目录作为兜底。
- 显示来源、资源 ID、版本/revision、checksum、大小、状态、错误和引用任务数。
- 资源状态：未下载、下载中、就绪、失败、已归档。
- 已被任务引用的版本不得覆盖；更新产生新版本。
- 正式任务执行过程中不得临时联网下载 Tokenizer。

当供应商 usage 缺失且 Tokenizer 无法加载时：冒烟测试可降级为仅延迟测试；要求 Token 指标的性能任务预检失败并禁止启动。

### 8.5 数据集管理（F-07）

#### 8.5.1 分类

- **性能数据集：** 受控合成数据、本地模板或经脱敏的真实流量样本，用于控制 Token 长度和缓存条件。
- **质量数据集：** 固定题目、参考答案和评分器，用于客观能力回归。

两类资源独立管理，不允许把质量题库直接作为标准性能压测输入。

#### 8.5.2 内置质量基准

- IFEval：指令遵循。
- C-Eval：中文知识精选子集。
- MMLU：通识知识精选子集。
- GSM8K：数学推理。
- MGSM：中文子集。
- HumanEval、MBPP：代码生成。

每个版本登记来源、license、版本/revision、checksum、样本数、语言、能力标签、默认 Prompt、评分方式和下载状态。上架前逐项审核 license；平台支持不代表自动取得再分发权。

#### 8.5.3 自定义数据集

- 格式：UTF-8 JSONL 或 CSV。
- 单文件上限：100 MB。
- 上传后预览前 20 条，并映射 prompt/messages、answer 和 tags 字段。
- 支持单轮 prompt 和多轮 messages schema。
- 全文件校验通过后才创建版本，不接受部分成功。
- 保存记录数、checksum、字段映射和 Token 长度分布。
- 上传页面提示用户先完成脱敏；首版不自动识别或删除 PII。

#### 8.5.4 生命周期

- 数据集在“测试资源”页面由人工下载或上传，下载后校验版本和 checksum。
- 任务只使用状态为“就绪”的本地缓存。
- 已被任务使用的版本不可编辑，只能新增版本或归档。
- 下载失败可重试，不影响已经就绪的其他版本。

### 8.6 测试方案模板（F-08）

- 系统内置：冒烟、快速基线、标准基线、并发梯度、固定 RPS、稳定性、轻量质量。
- 系统内置模板不可直接修改，只能复制。
- 自定义模板未被任务使用前可编辑；首次被任务使用后，再修改即创建新版本。
- 历史任务始终引用原版本；模板只允许归档，不提供物理删除。
- 不提供拖拽式工作流编排器。

模板可配置：测试类型、目标场景、数据集版本、Tokenizer、生成参数、流式模式、预热、负载方式、请求数、重试、超时、目标限制和备注。

### 8.7 任务创建与强制预检（F-09）

#### 8.7.1 创建流程

1. 新建任务或从历史任务创建复测草稿。
2. 选择测试方案模板和版本。
3. 选择一个或多个模型部署；默认按顺序串行运行，可切换为并行。
4. 确认数据集、Tokenizer、生成参数、负载和限额。
5. 查看预计请求数、最长时长和最大 Token 消耗。
6. 执行强制预检。
7. 预检通过后冻结快照并进入 FIFO 队列。

#### 8.7.2 参数一致性

同一横向比较默认共用 messages、temperature、top_p、max_tokens、stop 和 seed。允许对单目标覆盖参数，但任务和报告必须标记为“非严格可比”并列出差异。

#### 8.7.3 强制预检项

- 连接与模型部署处于可用状态，API Key 已配置。
- Base URL 通过域名/CIDR 白名单、DNS/IP、TLS 和禁止重定向规则。
- 流式/非流式能力满足方案。
- 数据集、Tokenizer 和具体版本处于就绪状态。
- 输入长度与 `max_tokens` 不超过模型上下文和输出限制。
- 并发、RPS、RPM、TPM、请求数、总 Token 和任务时长不超过连接及系统硬限制。
- PostgreSQL、普通 Worker、报告/缓存目录与剩余磁盘空间正常。
- 代码任务要求代码 Worker 在线且沙箱镜像可用。

硬条件失败时任务保留为草稿，禁止入队；风险提示项允许用户二次确认。预检结果和确认行为写入任务记录及审计日志。

### 8.8 队列、状态与异常恢复（F-10）

#### 8.8.1 队列规则

- PostgreSQL 是唯一数据库和持久化任务队列。
- 等待 Run 按入队时间 FIFO 执行，不提供优先级、插队或预约。
- 全局默认最多同时运行 4 个 Run，可在部署/系统配置中修改；任务页面不能绕过。
- 串行任务一次占用一个 Run 名额；并行任务按实际并行 Run 数占用。
- 每个连接仍受独立并发、RPS、RPM 和 TPM 上限约束。
- 排队中的任务可以取消。

#### 8.8.2 任务状态

`草稿 → 排队中 → 运行中 → 已完成/部分完成/失败`

取消分支：`排队中/运行中 → 取消中 → 已取消`

- 所有 Run 正常结束：已完成。
- 至少一个 Run 完成，另有失败或取消：部分完成。
- 所有 Run 均失败且没有有效结果：失败。
- 用户取消整项任务：已取消；已产生的数据仍保留。
- 单请求失败不会直接导致 Run 失败；Run 执行结束后将错误率作为结果。
- 预检失败：保持草稿，不进入队列。

#### 8.8.3 Worker 异常

- Worker 使用数据库 lease 和 heartbeat 认领 Run。
- 尚未开始的排队 Run 可由其他 Worker 重新认领。
- 执行中的 Worker 失联后，Run 标记为“中断失败”，保留已完成请求。
- 不从中断位置自动续跑；用户可人工重试，生成新的 Run。

### 8.9 执行模式与负载（F-13）

#### 8.9.1 输入方式

- 单条 Prompt：用于冒烟。
- 内置长度模板：用于标准性能测试。
- JSONL/CSV 数据集：用于性能或质量任务。
- 多轮 messages：按会话顺序执行，多个会话可并行。

#### 8.9.2 内置长度预设

| 名称 | 目标输入 Token | 最大输出 Token | 规则 |
|---|---:|---:|---|
| 短 | 256 | 128 | 默认启用 |
| 中 | 2K | 512 | 默认启用 |
| 长 | 8K | 1K | 默认启用 |
| 超长 | 32K | 2K | 仅全部目标支持时可选，P1 |

输入由对比组 Tokenizer 生成并在预检中校验上下文窗口。正式性能请求使用 Token 长度相同但内容不同的输入，减少 Prompt/KV Cache 命中对结果的抬高；如供应商返回缓存 Token 信息则单独保存。首版不建设专门的缓存命中基准。

#### 8.9.3 负载模式

- 固定并发：维持指定并发数，前一个请求结束后补发。
- 固定 RPS/open-loop：按目标到达率调度，不因已有请求变慢而降低目标发送节奏。
- 阶梯负载：按预设并发或 RPS 等级和持续时间逐级执行。

open-loop 必须设置最大 in-flight。达到上限时，尚未发送的计划请求记为“客户端调度丢弃”，不计为供应商失败；报告同时展示目标 RPS、实际发送 RPS 和调度丢弃数。

#### 8.9.4 默认规模

| 模板 | 默认规模 |
|---|---|
| 冒烟 | 流式、非流式各 1 次 |
| 快速基线 | 每种长度、每种响应模式 20 个正式请求 |
| 标准基线 | 每种长度、每种响应模式 100 个正式请求 |
| 阶梯压测 | 每个负载等级持续 3 分钟 |
| 稳定性 | 持续 30 分钟 |

全部数值允许在模板限制内修改，并受连接硬限制约束。

#### 8.9.5 冷启动与预热

- 正式任务默认先发送 3 个预热请求。
- 第 1 个请求单独记录为冷启动样本；预热请求不计入稳态汇总。
- 正式请求在预热结束后开始，报告分别展示冷启动和预热后稳态性能。
- 用户可以在模板允许范围内调整预热数，但不得把冷启动和稳态混合统计。

### 8.10 多轮、Tool Calling 与扩展字段（F-21）

#### 8.10.1 多轮

- 数据集通过 `messages` 定义多轮会话。
- 同一会话按顺序发送并携带历史消息；不同会话可并行。
- 保存每轮和整段会话的延迟、Token、错误和响应。
- 某轮失败时保留此前轮次，并将会话标记为“中断”。

#### 8.10.2 Tool Calling

- 支持在请求中传入 `tools` 和 `tool_choice`。
- 校验流式与非流式返回的 `tool_calls` 结构、函数名和参数字符串。
- 尝试解析函数参数 JSON；解析失败记兼容性错误并保留原始值。
- 不实际执行工具，不进行 Agent loop，不把工具调用质量纳入综合评分。

#### 8.10.3 推理与供应商扩展字段

- 保留完整原始响应 JSON。
- 对已知 `content`、`reasoning_content`、`reasoning_tokens`、缓存 Token 和 service tier 字段做结构化提取。
- 未识别扩展字段原样保留，不因未知字段判定失败。
- 只有语义一致、口径明确的字段可以聚合比较。

### 8.11 客观质量评测与代码沙箱（F-14）

#### 8.11.1 质量参数

- 默认 temperature=0，每个样本请求 1 次。
- 模板可以配置每样本重复 2–5 次；只有重复次数大于 1 时计算代码 `pass@k`。
- 质量请求仅可对临时网络错误、超时、429 和 5xx 做有限自动重试；默认最多重试 2 次，并记录每次 Attempt。
- 400/404/422 等配置或兼容性错误不自动重试。

#### 8.11.2 自定义客观评分器

- exact match。
- normalized exact match。
- regex match。
- 多项选择准确率。
- 数值容差。
- 代码单元测试。

首版不允许用户上传或执行任意 Python 评分脚本，不提供 LLM-as-a-Judge。

#### 8.11.3 代码执行安全

- HumanEval、MBPP 和自定义代码测试在独立代码 Worker 上执行。
- 每次执行使用隔离、短生命周期容器，默认禁止外网。
- 设置 CPU、内存、运行时间、进程数、文件大小和工作目录限制。
- 测试用例与执行环境不得把宿主机凭证、数据库或内部网络暴露给模型代码。
- 保存编译/运行状态、标准输出、标准错误和测试结果；输出进入报告前做凭证脱敏。
- 普通 Web/API 和普通 Worker 不直接执行模型生成代码。

### 8.12 监控、取消、重试与复测（F-11、F-12）

#### 8.12.1 任务监控

页面每 2–5 秒刷新，显示：

- 任务和 Run 状态、排队位置、进度、已用时间和预计剩余时间。
- 当前并发、目标/实际 RPS、成功率、错误率。
- Latency、TTFT、Token 速度和吞吐的当前汇总。
- 错误按 HTTP 状态、类型和最近发生时间聚合。

浏览器不逐 Token 实时渲染所有响应，避免 UI 与数据库压力。

#### 8.12.2 取消

- 支持取消整项任务或单个 Run。
- 点击取消后 5 秒内停止发送新请求。
- 已在途请求允许在超时上限内完成；状态先进入“取消中”。
- 最终保留部分数据并标记已取消/不完整。
- 取消不回滚已写入的请求、指标和日志。

#### 8.12.3 人工重试

- 性能请求不自动重试。
- 失败 Run 的人工重试创建新 Run，不覆盖原 Run。
- 新 Run 记录来源 Run，并使用用户确认后的当前连接与密钥。

#### 8.12.4 一键复测

- 仅支持人工触发，不提供定时复测。
- 点击后创建新草稿，不直接启动。
- 复制原任务的数据集版本、Tokenizer、生成参数、负载和目标。
- 使用当前有效 API Key，不复制历史密钥。
- 展示 Base URL、model ID、价格、汇率和限额的变化。
- 用户确认后进行预检并进入队列；原任务不变。

### 8.13 结果、指标与逐请求详情（F-15）

#### 8.13.1 结果层级

- 任务汇总：多目标总体进度、状态和比较入口。
- Run 汇总：单个模型部署/场景的性能、质量、成本和错误。
- 请求明细：输入、输出、时序、Token、usage、状态和错误。
- Attempt 明细：质量请求的每次实际重试。

#### 8.13.2 原始结果

- 完整 Prompt/messages、模型回答、原始响应 JSON 和错误正文长期保留。
- 保存供应商 request ID、响应 header 白名单字段和状态码。
- API Key、Authorization header、Cookie 和已知凭证字段在写日志/报告前脱敏。
- 原始结果不可编辑；人工备注单独存储。

### 8.14 结果对比（F-16）

#### 8.14.1 选择范围

用户可以选择任意终态历史 Run 进行查看和对比。平台自动检查：

- 测试类型与场景。
- 数据集及版本。
- Tokenizer、版本和 Chat 模板。
- Prompt、生成参数和流式模式。
- 负载方式、请求量、并发或 RPS。
- 冷启动、预热和稳态统计口径。

全部一致标记“严格可比”；有差异仍可查看，但标记“非严格可比”，展示差异项，不合并统计、不生成排名。

#### 8.14.2 可视化

- 指标对比表。
- TTFT、总耗时、TPOT 的分位数条形图或箱线图。
- 实际 RPS、吞吐和错误率时间序列。
- 阶梯负载曲线。
- 错误分类堆叠图。
- 冷启动与稳态对比。
- Token 成本对比。
- 质量得分表和柱状图。

不使用雷达图、综合评分或“最佳供应商”标签。

### 8.15 人工备注、导出和静态报告（F-17、F-18）

#### 8.15.1 人工备注

- 用户可对任务或 Run 添加和修改文本备注。
- 修改备注不改变原始结果，也不自动重新生成报告。
- 用户再次点击“生成静态报告”时，新报告版本快照当前备注。

#### 8.15.2 机器可读导出

- 提供汇总 CSV。
- 提供完整任务/Run/Request JSON。
- 仅在平台中人工下载，不自动复制到静态报告目录。
- 导出必须脱敏 API Key、认证 header 和其他已知秘密。

#### 8.15.3 报告生成条件

仅以下终态允许生成：已完成、部分完成、失败、已取消。报告必须标记任务状态、缺失数据和未完成 Run。草稿、排队中、运行中和取消中不可生成。

#### 8.15.4 生成与版本

- 仅在用户点击“生成静态报告”时生成，不在任务结束或备注变化后自动生成。
- 每次生成创建新的不可变报告版本，旧版本长期保留。
- 记录版本号、生成时间、任务状态、备注快照和目录位置。
- 报告生成失败不改变评测任务状态；显示错误并允许重试生成。

#### 8.15.5 静态报告结构

- 多页纯静态 HTML，可在断网环境的桌面 Chrome 中打开，不依赖 CDN。
- 首页、摘要、性能、质量、成本、错误和对比页面不包含完整 Prompt、完整回答和完整错误正文。
- 所有完整请求内容只放入独立 `request-details.html`。
- 外发人员删除 `request-details.html` 后，其他页面仍可完整查看；摘要页不得依赖该文件加载数据。
- 静态包内不另行复制含完整请求内容的 JSON/CSV。
- 报告展示供应商名称和 Base URL，不展示 API Key。
- 即使内部报告，认证信息仍必须脱敏。
- 视觉采用深色技术/可观测性风格，青蓝紫强调色，支持指标卡、动画图表、悬停、缩放、筛选、吸顶导航、异常与峰值标记，并提供浅色打印样式。

### 8.16 系统设置、审计与历史清理（F-19、F-20）

#### 8.16.1 网络白名单

- 白名单通过后台页面维护并存入 PostgreSQL，不通过 `.env` 配置。
- 支持允许的域名和 CIDR。
- 云元数据、loopback、link-local、multicast/broadcast 和其他永久禁止地址不可通过白名单放行。
- Base URL 保存、连接测试、任务预检和实际请求前均重新解析并校验。
- 防止 DNS rebinding；不自动跟随重定向。
- 修改白名单需要输入确认文本，展示受影响连接，并写审计日志。

#### 8.16.2 审计日志

记录时间、来源 IP、动作、目标对象、结果和脱敏差异。至少覆盖：供应商/连接配置、API Key 替换、任务创建/取消/重试、报告生成、白名单修改和历史清理。不得记录 API Key 或完整 Prompt/回答/错误正文。

#### 8.16.3 数据保留与清理

- 任务、逐请求明细、日志、备注和静态报告默认长期保留，不自动清理。
- 配置对象无物理删除入口；任务数据仅通过“清理历史任务数据”执行物理清理。
- 清理条件：截止日期和终态状态；草稿、排队中、运行中、取消中的任务不可清理。
- 执行前预览任务数、请求明细数、报告数和预计释放空间。
- 删除范围：任务、Run、请求/Attempt、业务日志、备注和报告文件。
- 保留范围：供应商、连接、模型、对比组、Tokenizer、数据集、模板和不含业务正文的清理审计记录。
- 用户必须输入指定确认文本后才可执行；执行结果不可恢复。

## 9. 指标口径

### 9.1 请求级性能指标

| 指标 | 定义 | 适用模式 |
|---|---|---|
| 总耗时 / Latency | 从发出请求到完整响应结束的时间，单位 ms | 流式、非流式 |
| TTFT | 从发出请求到收到第一个非空输出 Token/内容事件的时间，单位 ms | 流式 |
| TPOT | 从首个输出 Token 到最后一个输出 Token 的时间除以后续输出 Token 数，单位 ms/token | 流式且输出 Token > 1 |
| ITL | 相邻两个输出 Token 到达时间间隔；请求级保存序列，汇总显示统计值 | 流式 |
| 平均生成速度 | 从首个到最后一个输出 Token 的生成 Token 数除以生成时长，单位 token/s | 流式 |
| 端到端平均输出速度 | 输出 Token 数除以总耗时，单位 token/s | 流式、非流式 |
| 峰值速度 | 任意连续 10 个输出 Token 滑动窗口内的最大速率 | 流式且至少 10 Token |
| 峰值 TPS | 任意连续 1 秒窗口内收到的最大输出 Token 数 | 流式 |
| 输入/输出/总 Token | 分别记录供应商 usage 与平台 Tokenizer 两套数值 | 流式、非流式 |

若供应商流式分片与 Token 边界不一致，平台必须先使用指定 Tokenizer 对累计文本统一编码，不能简单把 SSE chunk 数当作 Token 数。

### 9.2 聚合指标

- 请求总数、成功数、失败数、取消数、调度丢弃数。
- 成功率和按类型错误率。
- 实际请求吞吐量 req/s。
- 输出 Token 吞吐量和总 Token 吞吐量 token/s。
- 对适用指标提供 mean、min、max、P50、P90、P95、P99。
- 冷启动、预热和正式稳态数据独立聚合。
- 非流式请求的 TTFT、TPOT、ITL、峰值速度和峰值 TPS 显示“不适用”，不得以总耗时替代。

### 9.3 Token 双口径

- 供应商 usage 用于账单成本；平台 Tokenizer 用于性能对齐和估算。
- 两套数据均存在时显示差值和差异率，不自动覆盖。
- usage 缺失不是请求失败；显示“供应商未返回 usage”。
- 供应商 usage 缺失且本地 Tokenizer 不可用时，不计算任何 Token 派生指标。

## 10. 错误分类、超时与重试

### 10.1 错误分类

| 分类 | 示例 |
|---|---|
| DNS/连接 | DNS 失败、连接拒绝、路由失败 |
| TLS | 证书无效、握手失败 |
| 超时 | 连接、首 Token、流式 chunk idle、总请求超时 |
| 鉴权 | 401、403 |
| 协议/配置 | 400、404、3xx、422、响应 schema 不兼容 |
| 限流 | 429，保存脱敏后的 Retry-After |
| 供应商服务 | 5xx |
| 流式协议 | SSE 格式错误、流中断、缺少结束标记 |
| 内容/结构 | 空响应、无 choices、tool_calls 参数 JSON 无法解析 |
| 客户端调度 | open-loop 达到 max in-flight 后未发送 |
| 用户取消 | 用户取消导致请求停止或中断 |

保存脱敏错误正文及供应商 request ID。错误正文可能包含 Prompt 或响应片段，因此只出现在平台详情和静态报告独立明细页中。

### 10.2 默认超时

| 超时项 | 默认值 |
|---|---:|
| 连接超时 | 15 秒 |
| 首 Token 超时 | 300 秒 |
| 流式 chunk idle 超时 | 120 秒 |
| 单请求总超时 | 30 分钟 |

连接可配置默认值，模板可在系统边界内覆盖；四类超时必须分别记录和展示。

### 10.3 重试策略

- 性能请求不自动重试。
- 质量请求仅对网络临时错误、超时、429 和 5xx 有限重试；每次 Attempt 独立记录。
- 400/404/422、鉴权和协议错误不自动重试。
- Worker 中断不自动断点续跑。

## 11. 安全、隐私与数据治理

### 11.1 访问边界

- 首版无登录鉴权，只允许通过可信公司网络、VPN 或统一网关访问。
- 生产部署必须在网络层限制来源，不得直接暴露公网。
- 未来引入 SSO 时复用已预留审计身份字段，不在首版实现伪权限体系。

### 11.2 密钥与凭证

- API Key 使用应用层加密后存入 PostgreSQL；主密钥仅由受保护 `.env` 注入。
- PostgreSQL 连接信息由 `.env` 配置，不写入仓库、报告或审计。
- UI 不回显密钥；日志、CSV、JSON 和静态报告必须统一脱敏。
- 任何 Authorization、Cookie、Proxy-Authorization 或已知密钥字段不得进入可搜索业务日志。

### 11.3 业务数据

- Prompt、模型回答和错误正文不做应用层字段加密。
- 外部 PostgreSQL 必须启用 TLS、存储加密和备份保护。
- 静态报告目录和备份介质按内部敏感数据管理。
- 自定义数据集上传前提示脱敏；首版不承诺自动 PII 识别。

### 11.4 TLS 例外

“忽略 TLS 错误”默认关闭、按连接配置、需要风险警告和二次确认。相关连接、任务、结果和报告均显示“不安全 TLS”标签。该开关不放宽 SSRF 白名单或永久禁止地址。

## 12. 技术与部署约束

### 12.1 技术栈

- 后端：Python、FastAPI、SQLAlchemy 2、Alembic、Pydantic。
- 前端：React、TypeScript、Vite。
- 数据库与队列：PostgreSQL，唯一数据库。
- 执行引擎：EvalScope，通过 Python API 调用，禁止拼接 shell 命令字符串。
- 普通 Worker：运行性能、协议和非代码质量评测。
- 代码 Worker：部署在独立主机/VM，通过短生命周期容器执行不可信代码。

### 12.2 部署

- Web/API 与普通 Worker 使用 Docker Compose 部署。
- PostgreSQL 使用外部服务，连接信息通过 `.env` 配置。
- 静态报告目录和 Tokenizer/数据集缓存使用持久化目录。
- 首版不使用 Kubernetes。
- 报告目录和主密钥必须纳入运维备份；Tokenizer 缓存可重新下载，不要求强制备份。

### 12.3 开源边界

- EvalScope 为唯一运行时评测引擎。
- OpenCompass 不作为独立服务部署；需要的 OpenCompass 数据集或后端能力通过 EvalScope 可用能力接入。
- token-speed-tester 仅作为指标和报告视觉参考，不引入依赖。
- 平台不复用 EvalScope dashboard，独立建设本需求定义的管理界面。

## 13. 非功能需求

### 13.1 容量

首版设计和验收基准：

- 约 30 家供应商以内。
- 500 条服务连接。
- 2,000 个模型部署。
- 10,000 个历史任务。
- 10,000,000 条请求/Attempt 记录。
- 默认最多 4 个并行 Run。

达到上述规模前不引入分区表或独立分析存储；仅当实际监控显示查询、维护或存储达到瓶颈时再升级。

### 13.2 性能

- 常用列表、筛选和任务汇总接口在基准容量下 P95 不超过 2 秒。
- 任务监控数据 2–5 秒内刷新。
- 取消指令 5 秒内停止新请求调度。
- 大型逐请求列表必须分页，不一次加载完整响应正文。

### 13.3 可靠性与一致性

- 任务状态、Run 认领和结果写入以 PostgreSQL 事务为准。
- 创建任务、取消、人工重试和生成报告必须防止重复点击产生重复副作用。
- 报告文件生成采用临时目录完成后再发布为正式版本，失败不得留下“已完成”空报告。
- 文件清理与数据库清理需要记录一致性结果；部分失败时显示待人工处理项。

### 13.4 兼容性与可访问性

- 仅保证最新稳定版桌面 Chrome。
- UI 和静态报告使用中文；TTFT、TPOT、ITL、TPS 等缩写保留并提供中文解释。
- 不做首版国际化和移动端适配。
- 基础键盘焦点、表单标签、错误文本和颜色对比必须可用，关键信息不得只靠颜色表达。

### 13.5 备份与恢复

平台不内置备份功能。部署文档必须说明：

- 外部 PostgreSQL 的备份和恢复职责。
- 静态报告目录的备份和恢复职责。
- API Key 应用主密钥的独立安全备份；丢失后已有密文无法恢复。
- Tokenizer/数据集缓存的重建方式。

| 风险/依赖 | 影响 | 应对 |

| 测试环境网络波动 | TTFT 和吞吐受到客户端链路影响 | 固定执行节点、记录时间和连接条件、使用重复与分位数 |
| 数据集 license 变化 | 无法继续分发或使用 | 每版本记录 license，下载前审核，不全量搬运 |
| 不可信代码逃逸 | 内网和数据安全风险 | 独立主机、短生命周期容器、无网、资源限制、无凭证 |
| 长期保留导致磁盘增长 | 查询和报告生成失败 | 健康面板容量预警、人工预览清理、外部备份策略 |
| 无登录导致误操作 | 配置或清理被内部人员误触 | 可信网络、二次确认、审计日志；后续接入 SSO |
| EvalScope 升级改变口径 | 历史数据不可比 | 任务快照引擎版本，升级前做回归，不改写历史结果 |

## 18. 未来演进方向

以下内容不属于首版承诺，只有出现真实业务需求后再立项：

| 方向 | 可能能力 | 启动条件 |
|---|---|---|
| 身份与权限 | SSO、角色权限、操作者身份 | 访问人群扩大或审计要求提升 |
| 外部集成 | 稳定自动化 API、Webhook、定时任务 | 出现明确调用方和 SLA |
| 价格同步 | 对接供应商管理系统 | 外部系统提供稳定模型映射和版本接口 |
| 主观质量 | LLM-as-a-Judge、人工盲评 | 明确评审模型、标尺和成本预算 |
| 更多模型类型 | Embedding、Rerank、图像、音频 | 文本 LLM 首版稳定且业务提出需求 |
| 高级存储 | PostgreSQL 分区、对象存储、分析库 | 真实容量或查询指标超过首版基线 |
| 高可用部署 | Kubernetes、弹性 Worker | 单机 Compose 无法满足可用性或吞吐 |
